# OmniCore.Services.User.Infrastructure

## Purpose
Persistence and messaging for the User service: EF Core on its own PostgreSQL database, the repository, and MassTransit wiring.

## What is inside
| File | What it does |
|---|---|
| `Persistence/Contexts/UserDbContext` | Schema `users`; applies the configurations; adds the transactional outbox/inbox tables. |
| `UserDbContextFactory` | Design-time factory so `dotnet ef` works (startup project `User.Api`). |
| `Persistence/Configurations/*` | `user_profiles` (soft delete, audit columns; no unique index on username/e-mail; `TenantProfiles` ignored), `user_settings` (unique `user_id`), `user_addresses` (cascade delete), shared id converters. |
| `Persistence/Repositories/UserProfileRepository` | Tracked load with settings and addresses (`!IsDeleted`), read-only load, `ExistsAsync`. |
| `Persistence/Migrations/` | `InitialUser`, generated by CI (no SDK in the agent sandbox). |
| `DependencyInjection` | `AddUserInfrastructure` (shared infra, DbContext, unit of work, MassTransit with the outbox and this service's consumers, Scrutor scan) and `UseUserInfrastructureAsync` (applies migrations). |

## Depends on / used by
`User.Application`, `Shared.Infrastructure`. Used by Api. EF Tools are no longer referenced here (UI1); the design package is in Api.

## Rules for this layer
Entity change and migration in the same commit. Create migrations with `pwsh scripts/shells/add-migration.ps1 -Service User -Name <Name>`; a pending model change fails startup (`PendingModelChangesWarning`), and the integration tests catch it.

## Known gaps
- Migrations run in every replica at startup (same as A18).
- Queue names are not yet service-scoped (I3).
